# 第6关怪物警觉后不攻击：修复记录

## 原因和证据

原代码发出 `50793 WarningResp` 后没有激活怪物移动；攻击 tick 对距离超过 5 的怪物直接跳过。已有 ChaseStartResp 控制的是主角，不能代替怪物走位。

依据 `D:/抓包数据/第一次创角色.json`：

- idx 1983/1984：两只前排怪警觉；1988 起下发怪物 MoveResp。
- idx 2005：后排怪 1000603 警觉。
- idx 2010–2076：后排怪通过 50761/type=1 靠近；每约 66ms 位移 0.33，angularSpeed=5。
- idx 2076：50761/type=4 停步；2077：220310110101 普攻。
- 第二、第三波同样包含警觉、移动、停步和 220310110101/220310210101 出手。
- 客户端 `SGEngine.Core/ComponentMove.cs` 的 OnBattleMove：MoveResp.angularSpeed 实际作为移动速度使用；type=1 导航，type=4 停步并对齐位置。
- Luban `monsterskillconfig.json` 的 Id=13 确认后排技能为 220310110101/220310210101。

## 实现范围

- 仅为 10200101、10200102、10200103 启用当前波怪物移动，沿用原攻击距离，不扩大范围。
- 警觉按场景对象 ID 绑定；重复提示不重置移动或冷却。
- Actor 每约 66ms 推进移动，速度 5；推进上一帧位置后，按玩家位置更新下一目标。
- 先下发停步，再结算和下发攻击。攻击冷却仍为原 1000ms，不随移动 tick 加速。
- 暂停发送停步，恢复不追补暂停时间；死亡、结束、旧波次不继续推进新会话。
- 每波重新激活警觉；主动技能提前 return 的分支也补齐后排警觉。
- 第二、第三波接回已有第6关普攻定义，避免后排错误使用近战技能。近战/远程沿用已记录的 25/26 伤害定义，未重新设计伤害公式。

按 doudi-server-reference 的 Java 8、Actor 串行及局部修改约束实现；fuwu 未修改，第11关战报身份修复保留。
